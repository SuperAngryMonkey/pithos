# Pithos v0.7.0 Release Notes

**Mesh view.** The dashboard now shows a card per host — this one and every
configured peer — with live resource figures.

## Peers are contacted over the tailnet only

This is enforced in code, not left to configuration. A peer address must
resolve entirely into `100.64.0.0/10`; anything else is logged as an error and
dropped at startup, so a peer cannot be pointed at a LAN or public address by
mistake. On a host with a public bridge that distinction matters.

## Configuration

```
PITHOS_PEERS=100.64.0.2:8080,admin:otherpass@100.64.0.3:8081
PITHOS_MESH_USER=admin
PITHOS_MESH_PASS=...
PITHOS_MESH_TIMEOUT=6      # per-peer, seconds
PITHOS_MESH_CACHE_TTL=20   # seconds
```

Port defaults to 8080. Peers with their own credentials need those credentials
here; the mesh sends one user/password to every peer.

## What a card shows

Containers and VMs, core count and load, memory available against total, and
free space on the host's default storage. Peers are fetched in parallel, and an
unreachable peer renders as a card saying so with the reason — never a broken
dashboard.

## Also

`/api/status` gained `cores`, `load1`, `mem_total`, `mem_avail`, `store_name`,
`store_total` and `store_avail`, so the same figures are available to the MCP
and scripted clients. `GET /api/mesh` returns the whole set.
