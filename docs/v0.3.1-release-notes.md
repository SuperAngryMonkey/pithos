# Pithos v0.3.1 Release Notes

**Containers now start after a host reboot.**

## The bug

Pithos never set `onboot`. `pct clone` leaves it unset, which Proxmox treats
as off, so *every container Pithos has ever provisioned* stayed down after a
host power cycle — silently, until someone noticed the services were gone.

This was found the hard way: a power outage took a lab host down and none of
its containers came back.

## The fix

- `pithos-new` sets `--onboot` explicitly after cloning, **defaulting to on**,
  and prints which mode it used.
- New `--no-onboot` flag (and `ONBOOT=0` env) for the deliberate exception.
- The web UI clone form has a **START AT BOOT** checkbox, checked by default.
- The inventory shows a **NO BOOT** badge against any container that will not
  start after a host reboot, and `/api/containers` gained an `onboot` boolean
  so scripted clients and the MCP can see it too.

## Existing containers

This release does not modify containers that already exist — check them:

```bash
for v in $(pct list | awk 'NR>1{print $1}'); do
    printf '%-6s %-20s onboot=%s\n' "$v" \
        "$(pct config $v | awk '/^hostname/{print $2}')" \
        "$(pct config $v | awk '/^onboot/{print $2}')"
done
```

and set the ones that should come back up:

```bash
pct set <vmid> --onboot 1
```

The inventory's NO BOOT badge makes the same information visible at a glance.

## Files changed

- `scripts/pithos-new.sh` — `ONBOOT` (default 1), `--onboot` / `--no-onboot`, `pct set --onboot`
- `webui/app.py` — checkbox, passes the flag through, `onboot` in inventory + API, NO BOOT badge
